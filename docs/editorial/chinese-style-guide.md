# 中文编辑规范 v1

本规范用于在不改动英文原文的前提下，统一中文文章的编辑质量。适用对象包括人工编辑与自动化编辑流程；若具体任务另有经批准的书面要求，以更严格者为准。

## 忠实性

- 忠实性与完整性优先于文采。润色应改善准确度、清晰度与可读性，不得为追求流畅而删去事实、限定条件、因果关系、立场差异或不确定性。
- 保持原文的信息层级、论证方向和语气强度。原文的可能、倾向、估计、条件与例外，不得改写成确定结论。
- 可在段内拆句、合并短句或调整句序，但不得跨段移动论点。标题、正文、图注、引语和注释之间的内容也不得互相挪用。
- 数字、时间、范围、比较对象、主体和否定词必须逐项核对。无法从原文确认的内容不得自行补写。

## 中文语序

- 优先采用自然的中文主谓宾结构，先交代明确主体，再陈述动作与结果；避免照搬英语长前置修饰、被动语态和层层嵌套从句。
- 将过长英文句拆为逻辑完整的中文短句时，保留原有因果、转折、递进和条件关系。
- 指代必须清楚。“其”“这”“该”等代词若可能指向多个对象，应还原明确主体。
- 同一段中的句子可以重排以改善衔接，但不得改变信息先后所承载的强调关系。

## 术语表

默认使用下表译法。专业语境存在歧义时，以原文含义为准，并按“中文（English）”格式在首次出现时标注英文；后文使用已确定的中文译名。

| 英文 | 默认中文 | 编辑说明 |
| --- | --- | --- |
| agent | 智能体 | 指可感知、规划并执行任务的 AI 系统；不要泛化为“代理”。 |
| agentic | 智能体式；具备自主执行能力的 | 根据句法选用名词性或描述性译法，避免生硬使用“代理式”。 |
| generative AI | 生成式 AI | AI 保留大写。 |
| foundation model | 基础模型 | 涉及特定厂商命名时遵从官方名称。 |
| operating model | 运营模式 | 指组织如何配置职责、流程与能力，不等同于商业模式。 |
| workflow | 工作流 | 强调端到端业务过程时也可译为“业务流程”，全文保持一致。 |
| use case | 用例；应用场景 | 技术功能说明优先“用例”，业务叙述优先“应用场景”。 |
| governance | 治理 | 根据上下文可具体化为“AI 治理”“数据治理”或“公司治理”。 |
| resilience | 韧性 | 供应链、运营或组织语境中保留具体限定词。 |
| upskilling | 技能提升 | 指在原岗位或相近职责上提升能力。 |
| reskilling | 技能转型 | 指为新岗位或新职责重新培养技能。 |

## 专名

- 品牌名不强制翻译。公司、产品、模型、平台、机构、项目和人名优先采用其官方中文名；没有稳定官方译名时保留原文。
- 品牌与产品的大小写、连字符、数字和版本号按官方写法保留，例如 ChatGPT、GPT-4 和 Claude。
- 易混淆或对目标读者不透明的专名，首次出现可写为“中文名（英文名）”；后文使用一种形式并保持一致。
- 不把普通概念误作专名，也不为了形式统一而改写注册商标或来源方自定名称。

## 数字与单位

- 原文中的数字、百分比、币种、时间、倍数、区间和单位必须完整保留并核对，不得擅自换算、取整或改变统计口径。
- 阿拉伯数字与单位符号之间按通行写法处理：`35%`、`20°C` 不加空格；`10 km`、`5 GB` 加半角空格。中文计量单位可写为“10 万元”“3 个月”。
- 数值区间使用连接号并保留两端口径，如 `10%–15%`；若来源使用“以上”“不足”“约”等限定词，译文必须保留。
- 货币首次出现且可能歧义时写明币种，如“1 亿美元（USD）”。日期按中文阅读习惯书写，但不得改变日期精度。

## 标点与空格

- 中文正文使用中文全角标点，包括逗号、句号、冒号、分号、问号、感叹号与括号。
- 中文与英文、数字之间留空格，例如“采用 AI 提升效率”“覆盖 12 个市场”；标点前后不额外加空格。
- 连续英文、网址、代码、变量名、文件名和产品官方拼写内部不插入空格，也不将其标点改为全角。
- 中文书名使用书名号，文章标题可按语境使用引号；同一层级的列表与标题标点保持一致。

## 引语

- 直接引语使用中文双引号“”；引语中的引语使用中文单引号‘’。
- 保留说话者、来源、语气和限定词。不得把转述改成直接引语，也不得为了简洁拼接不同位置的话语。
- 引语可以在不改变含义的前提下修正明显的直译语序；涉及关键措辞、争议表述或专有概念时，应对照原文核验。
- 省略引语内容须使用省略号，并确保省略不会改变原意或隐藏重要条件。

## 网页噪音

网页噪音仅在确认是独立界面模块时整块删除。先识别块边界，再按下列代码记录；不要在正文段落内做关键词级清理。

| 代码 | 可删除的完整块 |
| --- | --- |
| `save_share_print` | 保存、分享、打印、复制链接等操作按钮组。 |
| `subscribe_newsletter` | 订阅简报、注册提醒、填写邮箱等推广模块。 |
| `cookie_language` | Cookie 同意、隐私偏好、地区或语言切换提示。 |
| `progress_widget` | 阅读进度、预计阅读时长、浮动进度控件。 |
| `duplicate_navigation` | 与正文无关且重复出现的面包屑、目录、上一篇／下一篇或站点导航。 |

完整正文句即使包含“保存”“分享”“打印”“订阅”“Cookie”“语言”“进度”或“导航”等相同词语，也不得仅凭关键词删除。无法确认块边界时保留原文并标记复核。

## 禁止事项

- 禁止新增原文没有的事实、案例、评价、解释、结论或行动建议。
- 禁止遗漏实质信息，尤其是限定条件、反例、风险、来源、时间范围和统计口径。
- 禁止跨段拼接论点，禁止改变标题层级，禁止将图注或侧栏内容伪装成正文。
- 禁止逐词硬译、保留不自然英文倒装，或用空泛成语和宣传语替代精确表达。
- 禁止仅凭关键词删除疑似网页噪音；禁止删除仍承担完整语义的正文句。
- 禁止修改英文原文、来源链接和未经授权的元数据。

## 来源差异

- 不同发布方的署名方式、研究口径、图表标注和编辑体例可能不同。编辑时保留必要的来源归属与图表口吻，不保留英文语法结构。
- 机构自称可按中文自然语序转换，例如将“our research”译为“本研究”或“我们的研究”，但不得将发布方观点改写为编辑者观点。
- 图表标题、轴标签、图例、注释和来源行应保持彼此对应；可以调整为简洁中文，但不得统一掉来源特有的统计口径。
- 同一术语在不同来源中含义不同时，按各自上下文处理，并在首次出现处保留必要的英文消歧，不为表面一致牺牲准确性。
