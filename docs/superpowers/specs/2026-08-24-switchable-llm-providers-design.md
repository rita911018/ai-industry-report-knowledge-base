# 可切换大模型供应商设计

## 1. 目标

把知识库问答后端从写死的 DeepSeek 客户端改为供应商中立接口，使同一套本地检索、证据引用和回答校验逻辑可以使用 DeepSeek 或阿里云百炼千问。切换供应商只修改服务器环境配置，不修改前端和业务代码。

## 2. 配置接口

服务器统一读取以下环境变量：

```text
LLM_PROVIDER=deepseek|qwen
LLM_API_KEY=...
LLM_MODEL=...
LLM_BASE_URL=...
```

- `LLM_PROVIDER` 必须是 `deepseek` 或 `qwen`。
- DeepSeek 未提供 `LLM_BASE_URL` 时使用官方 `https://api.deepseek.com`。
- 千问必须提供阿里云百炼工作空间对应的 OpenAI 兼容 `base_url`；服务器在其后调用 `/chat/completions`。
- `LLM_MODEL` 只从服务器环境读取，浏览器请求不能临时指定模型，避免未经授权地切换成本和能力边界。
- 为现有桌面启动方式提供兼容期：若没有 `LLM_PROVIDER`，但存在 `DEEPSEEK_API_KEY`，自动按 DeepSeek 旧配置启动；页面提示迁移到新变量。

## 3. 客户端架构

- 新建供应商中立的 `llm-client`，接收问题、检索证据和已解析配置。
- DeepSeek 与千问分别负责端点、模型参数、错误映射和响应内容提取。
- 两个供应商都使用 OpenAI 兼容 Chat Completions 消息结构。
- 千问启用 `response_format: { "type": "json_object" }`，系统提示明确包含 `JSON`，并为支持的混合思考模型设置 `enable_thinking: false`，保证返回值可解析。
- 两个供应商输出同一个回答对象：`answer`、`claims`、`limitations`、`insufficient`；随后继续经过现有 `validateAnswer` 校验，供应商不能绕过引用验证。

## 4. 模型与地址安全

- API Key 只存在服务器环境变量中，不写入 HTML、浏览器脚本、本地存储、日志或健康检查响应。
- `LLM_BASE_URL` 只在服务器启动时读取，不接受来自 `/api/ask` 的 URL。
- 千问地址必须使用 `https`，且主机属于阿里云百炼已配置的工作空间域名；DeepSeek 默认地址固定为官方域名。
- 未配置或配置不完整时，服务器可以正常提供文章浏览、筛选和本地搜索，但生成式问答返回明确的配置提示。

## 5. 健康状态与界面文案

- `/api/health` 返回通用字段：`llmConfigured`、`provider`、`model`，不返回 Key 或完整工作空间 URL。
- 首页状态文案改为“千问已连接”“DeepSeek 已连接”或“问答模型待配置”。
- 错误文案使用供应商中立语言，例如“问答模型认证失败”“问答模型请求超时”；诊断日志可包含供应商名称，但不得包含 Key。
- 兼容期保留旧的 `deepseekConfigured` 字段，只用于旧前端过渡；新前端不再依赖它。

## 6. 数据流

1. 本地 BM25 检索从 4,117 个全文片段中选出证据。
2. 服务器仅把命中的证据片段、标题、机构、日期和 chunk ID 发送给当前配置的模型。
3. 模型按统一 JSON 契约生成回答和引用。
4. 服务器验证所有引用 ID 都属于本次检索证据；无效引用导致回答失败，不直接展示。
5. 前端收到与供应商无关的统一响应，因此全局问答抽屉无需知道使用的是哪家模型。

## 7. 不在本次范围

- 不在浏览器中提供供应商或模型选择器。
- 不同时调用两个模型，也不自动比较回答。
- 不把 API Key 保存到项目文件或导出的独立 HTML。
- 不改变本地检索算法、证据数量或文章语料。

## 8. 测试与验收

- 单元测试分别验证 DeepSeek 和千问的端点、请求参数、JSON 解析和错误映射。
- 配置测试覆盖新变量、DeepSeek 旧变量兼容、未知供应商、千问缺少工作空间地址以及不安全 URL。
- 服务器测试验证健康状态不泄露 Key，且浏览器提交的模型名或地址不能覆盖服务器配置。
- 回归测试确认两个供应商都必须经过引用校验，缺少模型配置时文章浏览和本地搜索仍可用。
- 使用测试替身完成自动化验收；只有用户提供真实 API Key 后才进行真实供应商连通测试。
