# HR 雷达矩阵疏朗化与详情顺序调整设计

## 目标

解决 HR 优先矩阵中场景标签彼此贴近、视觉重量过高的问题，同时统一实时页面与独立 HTML 报告的详情阅读顺序。

## 矩阵视觉设计

- 保留 12 个矩阵场景、现有业务价值/可行性坐标及点击行为，不修改场景数据和评分。
- 点位改为“编号圆点 + 轻量文字标签”：未选中时取消整块实底、粗边框和重阴影；P0 与风险边界只通过编号圆点和文字状态表达。
- 每个标签使用固定的紧凑宽度，允许标题自然换成两行。相邻坐标之间必须保留可见空隙，不能再连成一整排卡片。
- 点位靠近矩阵左右边缘时进行边界约束，确保编号和场景名不被裁切；存储的矩阵坐标不变。
- 悬停、键盘聚焦和选中时才显示完整深色高亮面；点击区域仍覆盖编号和文字，保留清晰的焦点样式。
- 手机端继续使用现有两列列表式矩阵，不采用绝对定位；文字不得横向溢出。
- 独立 HTML 导出的矩阵同步采用相同的轻量标签和边界约束，打印行为保持不变。

## 详情顺序

实时矩阵右侧详情、完整场景库展开详情、独立 HTML 导出统一使用以下顺序：

1. 业务痛点
2. AI 价值｜可以做什么
3. 主要风险
4. 哪些公司做过
5. 证据锚点

没有公开可核验公司案例的场景仍在第 4 项明确显示缺口，不隐藏该板块。

## 回归与验收

- 在桌面视口验证 12 个 HR 点位的标签矩形互不重叠、左右边缘不裁切，选中项仍可打开右侧详情。
- 在 390px 手机视口验证两列矩阵无横向溢出。
- 自动化测试精确断言实时详情、展开详情和独立导出的五项标题顺序。
- legal、schema-v2 以及其他领域雷达继续使用同一渲染器，矩阵交互、目录、筛选、排序和导出数量不得回退。
