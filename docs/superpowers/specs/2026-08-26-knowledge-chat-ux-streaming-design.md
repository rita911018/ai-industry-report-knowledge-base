# 知识库问答体验与安全流式输出设计

日期：2026-08-26  
状态：已批准  
范围：主页右侧“问整个知识库”抽屉、问答接口及来源阅读入口

## 目标

把当前偏“验证结果展示”的问答抽屉改成紧凑、自然、可操作的聊天界面。用户按下发送后必须立即看到反馈；回答需要结构化、易扫读，同时继续遵守“只基于归档全文、来源可追溯”的产品原则。

## 已批准的产品行为

1. 支持“你好”“你能做什么”“谢谢”“再见”等常规闲聊，闲聊不调用全文检索或外部模型。
2. Enter 直接发送；Shift+Enter 换行；中文输入法处于组合输入状态时，Enter 不发送。
3. 提交按钮文案从“基于全文回答”改为“提问”。
4. 缩小抽屉标题、回答标题与正文尺寸，正文以约 14–16px、1.65–1.75 行高为基准。
5. 使用“安全流式”而不是未经校验的模型原始 token：接口依次发送检索、生成、校验状态；完整回答通过引用校验后，再按结构化区块发送给页面。
6. 回答根据问题自动组织为 3–4 个短栏目，例如“核心结论”“优先场景”“建议怎么开始”。不强制所有问题使用同一标题。
7. 不再向用户展示逐条 claim、单条 claim 下的引用标签及 limitations/“边界”段落。这些数据仍在服务器端用于校验。
8. 问答来源中删除“打开原文归档”；保留“中文全文”“官网原文”，若文章来自 PDF，再保留“原始报告 PDF”。点击中文全文仍在左侧安全阅读器中打开。
9. 删除历史提问区域及其 localStorage 读写。
10. 资料不足时必须明确回答：“这个问题我还在学习，目前归档资料不足以给出可靠结论。你可以换个问法，或先问我现有报告中的观点。”
11. 接口、网络或模型失败时必须显示：“刚刚没能完成回答，请再试一次。”并提供“重新提问”操作，禁止静默失败。

## 视觉与内容层级

视觉基调延续现有暖白纸张、深墨绿和鼠尾草绿，不增加新色。抽屉保留右侧研究助手定位，但减少大标题、粗边框和重复卡片。

内容从上到下为：

1. 紧凑标题栏：“问整个知识库”与一行范围说明。
2. 当前问题，以轻量用户消息样式显示。
3. 流程状态，使用短文字而不是占满一屏的加载卡片。
4. 结构化回答区，每个栏目一个标题与短段落或列表。
5. 精简“参考来源”，每篇来源只显示机构、标题、引用位置与允许的阅读入口。
6. 固定底部输入区、提问按钮和“Enter 发送 · Shift+Enter 换行”提示。

不显示历史问题、API Key 说明、逐条验证过程和单独的“边界”块。

## 回答数据合同

模型输出继续保留服务器需要的 `answer`、`claims`、`limitations`、`insufficient`，并新增必需的 `sections`：

```json
{
  "answer": "一句话摘要",
  "sections": [
    { "heading": "核心结论", "body": "短段落" },
    { "heading": "关键发现", "items": ["要点一", "要点二"] }
  ],
  "claims": [
    { "text": "可核验陈述", "kind": "source_fact", "citations": ["chunkId"] }
  ],
  "limitations": [],
  "insufficient": false
}
```

约束：

- `sections` 为 2–4 项；每项必须有非空 `heading`，且只能使用 `body` 或非空 `items`。
- `claims` 继续逐条绑定有效 chunkId，由现有验证器校验；前端不直接渲染它。
- `limitations` 继续保留在机器合同中，用于审计和判断；前端不渲染独立边界段落。
- `insufficient=true` 时不要求结构化事实栏目，接口返回统一友好学习提示和空来源。
- 来源列表仍从通过校验的 claims 推导，不能由模型直接提供。

## 安全流式接口

新增 `POST /api/ask/stream`，响应为 UTF-8 NDJSON，设置 `content-type: application/x-ndjson; charset=utf-8`、`cache-control: no-store` 和 `x-content-type-options: nosniff`。每行是一个完整 JSON 事件：

1. `{"type":"status","stage":"retrieving","message":"正在检索归档全文…"}`
2. 检索不足时直接发送 `insufficient` 事件，再发送 `done`。
3. 检索成功后发送 `generating` 状态。
4. 模型返回后发送 `validating` 状态；服务器执行完整 JSON 与引用验证。
5. 验证通过后依次发送 `answer_start`、若干 `section`、`sources`、`done`。
6. 处理中出现异常时，如果响应已经开始，则发送不含凭据和上游原文的 `error` 事件并结束；如果尚未开始，沿用标准 JSON 错误响应。

这是安全流式：用户会立即看到自然阶段进度，但未经验证的模型文字不会提前显示。现有 `POST /api/ask` 保留，保证内部测试和潜在旧客户端兼容。

## 前端状态机

问答抽屉只有以下状态：

- `idle`：显示欢迎语或最近一次回答，输入可用。
- `retrieving`：显示“正在检索归档全文…”。
- `generating`：显示“正在组织回答…”。
- `validating`：显示“正在核验来源…”。
- `streaming`：逐项追加已校验栏目与来源。
- `done`：输入恢复可用并聚焦。
- `insufficient`：显示友好学习提示，输入恢复可用。
- `error`：显示失败提示和“重新提问”，输入恢复可用。

重复提交在 busy 状态下被忽略；取消或关闭抽屉不泄露凭据，也不破坏页面文章浏览。解析 NDJSON 时使用增量缓冲，必须正确处理网络分块切断 JSON 行的情况。

## 来源阅读

- 结构化回答末尾的来源条目可点击“中文全文”，在左侧 iframe 阅读器打开。
- “官网原文”使用新窗口和 `rel=noreferrer`。
- PDF 存在时显示“原始报告 PDF”。
- 问答抽屉及来源阅读器中不再展示 snapshot/英文 Markdown 的“原文归档”入口。
- 现有 iframe sandbox、CSP 与 no-referrer 安全边界保持不变。
- 文章索引弹窗不属于本次问答改版范围，其归档入口保持不变。

## 错误与闲聊

闲聊采用本地规则，覆盖中英文问候、能力询问、感谢和告别。闲聊返回简短自然文字，不显示来源，不写入历史。

检索不足、模型报错、响应格式错误、断网和 NDJSON 解析失败均必须终止 busy 状态并给用户文字反馈。失败提示不展示 API Key、端点、上游响应体或堆栈。

## 测试与验收

采用测试驱动实现，至少覆盖：

1. 静态 DOM：删除历史提问和 reader 原文归档；按钮文案、Enter 提示存在。
2. 键盘：Enter 仅提交一次；Shift+Enter 和输入法组合 Enter 不提交。
3. 闲聊：问候、能力、感谢、告别不调用接口。
4. NDJSON：可处理一行跨多个网络 chunk、多个事件同一 chunk、尾部无换行。
5. 状态：retrieving → generating → validating → streaming → done 顺序正确。
6. 结构化输出：只渲染 sections 和精简来源，不渲染 claims、limitations 或原文归档。
7. 失败兜底：insufficient、HTTP 失败、流中 error、解析失败均有可见回答，且按钮恢复。
8. 服务器：流式端点状态码、响应头、事件顺序、引用校验和凭据隔离。
9. 兼容性：现有 `/api/ask`、文章浏览、左侧中文 reader、PDF 和官网入口不回退。
10. 视觉验收：桌面与 390px 手机无横向溢出，字号更紧凑，输入区保持可见。

## 非目标

- 不保存跨会话聊天记录。
- 不新增登录、云端会话、语音或附件功能。
- 不改变文章索引、文章弹窗和雷达页面内容。
- 不将 API Key 暴露到前端。
