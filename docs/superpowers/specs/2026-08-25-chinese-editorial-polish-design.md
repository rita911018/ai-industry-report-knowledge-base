# 中文全文编辑校订设计

## 目标

对知识库现有 469 篇 `中文全文.md` 做逐篇中文编辑校订，使其从“结构完整但偏硬译”提升为自然、专业、连贯的中文文章，同时保持对官网原文的完整忠实。

本项目独立于已确认但尚未执行的“首页导航与 51 篇概要”计划。中文全文校订期间先暂停该计划，避免同时重建阅读页和 corpus 造成产物覆盖。

## 当前基线

- 总文章数：469。
- 中文全文总量：约 2,858,806 个字符，平均每篇约 6,096 个字符。
- 来源分布：McKinsey 49、Anthropic 32、BCG 132、MIT 43、Bain 213。
- 当前 `work/translation-audit.json` 为 469/469 通过，但只验证标题、段落覆盖、数字、URL 和中文字符比例，不评价中文流畅度。
- 典型问题包括：英文语序、机械被动句、术语漂移、孤立英文界面词、`Save It For Later`、`Progress:`、`en`、分享/打印/订阅等网页功能文字，以及不符合中文阅读节奏的长句。

## 编辑原则

### 忠实性

- 不摘要、不删正文、不合并论点、不扩写观点。
- 不改变事实、数字、百分比、日期、币种、单位、公司名、产品名和模型名。
- 保留标题层级、段落顺序、列表、表格、链接、图注、脚注和来源说明。
- 引语可改为自然中文口吻，但不得改变说话人的立场、强度和限定条件。

### 中文流畅度

- 将英文从句顺序重组为自然中文语序，必要时在同一段内拆分长句。
- 减少机械的“进行、实现、对于……而言、被……所”等硬译结构，但不把专业表达口语化。
- 使用中文全角标点，统一中英文、数字和单位之间的空格。
- 同一概念在全库采用统一术语；容易歧义的专业词首次出现使用“中文（English）”，后续只用中文。
- 公司、产品、模型和正式框架采用官方名称，不强行翻译品牌专名。

### 网页噪音

允许删除与文章内容无关的页面功能文字，包括保存、分享、打印、订阅、Cookie、语言切换、孤立的 `en`、`Progress:` 和重复站点导航。

不得通过全库正则直接批量删除。每个删除项必须属于明确的噪音类别，并在逐篇校订记录中留下类别计数；正文中的同名词语不得误删。

## 批次顺序

按来源分批完成并独立验收：

1. McKinsey：49 篇。
2. Anthropic：32 篇。
3. BCG：132 篇。
4. MIT：43 篇。
5. Bain：213 篇。

每个来源内部按 `archiveIndex` 升序处理。每篇文章是最小原子单位；完成一篇才写回，失败时保留原译文并记录错误。

## 工作流

### 1. 建立中文编辑标准

新增版本化中文风格指南，包含：术语表、专名规则、数字与单位规则、标点规则、引用规则、网页噪音类别及禁止事项。所有批次共享同一版本，避免来源之间风格漂移。

### 2. 建立可恢复状态账本

为 469 篇文章记录：文章 ID、来源、索引、原文哈希、校订前中文哈希、校订后中文哈希、状态、校订批次、噪音删除类别、自动校验结果、抽查结果和时间戳。

状态只允许：`pending`、`in_progress`、`verified`、`needs_review`。再次运行时只处理 `pending` 和 `needs_review`；源文件哈希变化时，已完成记录自动回到 `needs_review`。

### 3. Codex 逐篇校订

只使用 Codex，不调用外部翻译模型或本地模型。每次任务同时读取 `英文原文.md`、当前 `中文全文.md` 和中文风格指南；输出完整校订版 Markdown，不输出摘要或解释。

普通文章整篇处理。超过 40,000 字符的文章按 Markdown 一级/二级标题切分为章节；每个章节都携带文章标题、全局术语表和前一章节的术语状态，最后重新组合并做整篇校验。

### 4. 双层自动校验

保留现有完整性校验，继续检查标题、URL、数字、段落覆盖和中文字符比例。

新增中文编辑校验，检查：

- 禁止的网页噪音残留。
- 孤立英文界面词和未解释的大段英文。
- 术语表中的禁用译法或同义漂移。
- 中英文标点混用、异常空格和重复标点。
- 译文长度异常变化。
- Markdown 标题、列表、表格、链接和图片结构破损。

自动校验只能发现风险，不能证明行文自然。每篇仍须由 Codex 做一次独立编辑复核；失败时进入 `needs_review`，不得生成最终 HTML。

### 5. 抽样与来源验收

每个来源至少抽查 10%，并强制覆盖：最长文章、最高分文章、含大量数字/表格文章、含引语文章和一个随机样本。抽查对照英文原文，检查忠实性、术语一致性、中文节奏和噪音删除边界。

来源批次只有在以下条件同时满足时才算完成：

- 该来源 100% 文章状态为 `verified`。
- 自动完整性与中文编辑校验全部通过。
- 抽样文章无阻断问题。
- 生成的中文 HTML 可正常阅读。

### 6. 重建知识库产物

每完成一个来源：

- 重新生成该来源的 `中文全文.html`。
- 重建 `work/knowledge/corpus.json` 与 `web/data/articles.js`。
- 在本地知识库检查文章列表、详情弹窗、全文阅读页和全局问答引用。
- 仅在验证完成后同步到桌面交付目录。

## 文件与组件边界

- `work/archive/**/英文原文.md`：只读事实基准，永不覆盖。
- `work/archive/**/中文全文.md`：唯一中文正文源文件。
- `work/archive/**/中文全文.html`：由 Markdown 生成，不手工编辑。
- `docs/editorial/chinese-style-guide.md`：版本化中文风格指南与术语表。
- `work/editorial/chinese-polish-ledger.json`：469 篇的可恢复状态账本。
- `work/editorial/chinese-quality-audit.json`：自动校验与来源验收结果。
- `src/editorial/`：扫描、分批、校验和状态更新工具；不负责生成文章内容。
- `src/readers/` 与 `src/knowledge/`：继续负责 HTML 和 corpus 生成，不复制编辑逻辑。

## 安全与可恢复性

- 每篇写回使用临时文件加原子重命名。
- 校订前保留哈希和 Git 版本；校验失败不覆盖已验证译文。
- 不修改英文原文、标题、评分、分类、来源 URL 或文章身份。
- 不在日志中写入 API key、环境变量或无关用户数据。
- 中途停止后可从状态账本继续，不重复处理已验证文章。

## 验收标准

- 469/469 篇状态为 `verified`。
- 现有完整性校验 469/469 通过。
- 新增中文编辑校验 469/469 通过。
- 五个来源分别完成至少 10% 的人工式抽查，并记录样本 ID。
- 文章 HTML、corpus 和浏览器索引从校订后的 Markdown 重建成功。
- 桌面部署与工作版本逐字节一致。
- 浏览器抽查文章不存在明显网页噪音、英文残留或机械硬译，且数字、链接与原文一致。
