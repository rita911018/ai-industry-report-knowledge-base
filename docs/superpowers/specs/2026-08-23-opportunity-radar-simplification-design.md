# HR 与法务 AI 机会雷达精简改版设计

日期：2026-08-23  
状态：方向已确认，等待书面设计复核

## 1. 改版目标

本次改版同时作用于“人力资源 AI 机会雷达”和“企业法务 AI 机会雷达”。目标不是增加更多管理框架，而是让业务负责人在一次浏览中回答三个问题：

1. AI 到底能解决哪个具体业务问题；
2. 点开以后，为什么值得做、风险在哪里、依据是什么；
3. 市场上是否已有可核验的公司实践。

两个雷达继续作为无需模型 API 的静态决策页运行。改版不改变 12 个场景的优先级、价值分、可行性分和矩阵位置，只改变标题表达、详情结构、证据呈现和页面长度。

## 2. 页面保留与删除

每个雷达只保留四部分：

1. 首屏：领域名称、核心判断、P0 数量和场景总数；
2. 价值 × 可行性矩阵：点击点位后定位并展开对应场景；
3. `AI 能解决哪些业务问题`：12 个可筛选、可展开的场景；
4. `建议优先启动的 3 个场景`：用三张紧凑卡片呈现首批 P0，不再展开成独立 90 天路线图。

从两个页面删除以下独立长章节：

- 90 天路线图全文；
- 治理门槛与 KPI 大页；
- 五家 Insight Radar 校准页；
- 页面末尾的全局来源目录。

必要的治理边界并入每个场景的“主要风险”，来源直接放在场景详情中。这样不会丢失决策信息，也不会要求用户在页面后半段来回寻找依据。

## 3. 场景详情统一为五项

每个场景展开后，只显示以下五项，顺序固定：

1. **业务痛点**：当前流程为什么慢、贵、易错或体验差；
2. **AI 价值｜可以做什么**：AI 介入哪一步，能产生什么业务价值；
3. **主要风险**：数据、准确性、公平、合规和人工责任边界；
4. **证据锚点**：一至三个可点击的官网原文或知识库原文链接；
5. **哪些公司做过**：公司名、做法、案例性质和可点击来源。

不再单列“代表实践”“价值依据”“可行性判断”“人工责任”。原有有用内容分别合并进“AI 价值”和“主要风险”。

### 3.1 公司案例的数据规则

每个案例记录以下字段：

- `company`：实际采用方，不用供应商名称代替客户；
- `summary`：一句话说明公司在哪个流程使用了什么能力；
- `sourceId`：必须指向一个可点击来源；
- `caseType`：`客户案例`、`公司披露`、`研究案例`或`警示案例`；
- `caveat`：供应商自报、已停止试验、未披露成效等必要局限。

查找顺序为：公司官网或正式披露 → 供应商客户案例 → 高可信研究或媒体。若没有足够可靠的公开材料，页面明确写“暂无公开可核验案例”，不使用模糊的“业内已有实践”，也不编造公司名。对于默认不应立项或明确禁止的场景，可以展示“曾试验后停止”的警示案例。

## 6. 证据与来源呈现

“证据锚点”不再是一串不可点击的文章标题，而是独立链接卡片。每张卡片显示：

- 来源机构；
- 文章或案例标题；
- 证据性质，例如管理研究、公司披露、供应商客户案例；
- 必要的局限说明；
- `查看原文 ↗`。

同一来源可以同时支撑“证据锚点”和“哪些公司做过”，但 UI 不重复展示完全相同的卡片；公司案例区域只说明实践，公司名链接到对应原文。

## 7. 数据与渲染器变化

场景对象收敛为以下核心字段：

```js
{
  id,
  number,
  title,
  priority,
  category,
  value,
  feasibility,
  matrix,
  problem,
  aiValue,
  risk,
  evidenceIds,
  companyCases: [{ company, summary, sourceId, caseType, caveat }]
}
```

渲染器只输出五项详情。来源对象继续保留 `title`、`publisher`、`url`、`evidenceType` 和 `limitation`，但不再生成全局来源章节。验证器新增以下约束：

- 两个雷达仍各有 12 个唯一场景和 3 个 P0；
- 每个场景都有非空 `problem`、`aiValue`、`risk` 和 `evidenceIds`；
- `companyCases` 必须是数组；有案例时，五个案例字段齐全且 `sourceId` 有效；
- 没有可核验案例时数组为空，由渲染器显示固定空状态；
- 每个标题以“用 AI”或“让 AI”开头，并明确写出业务动作；
- 所有证据和案例来源 URL 可解析，外部链接使用安全的新标签属性。

## 8. 视觉与交互

- “场景组合”改名为“AI 能解决哪些业务问题”。
- 场景标题作为列表最醒目的信息，优先级和分数退居辅助位置。
- 五项详情在桌面端采用两栏布局，“证据锚点”和“哪些公司做过”使用全宽；手机端全部单列。
- 来源与案例均可点击，键盘焦点样式清晰。
- 高风险与禁止场景在标题、风险区和案例区保持一致提示，不能只靠颜色表达。
- 打印时展开全部场景，但不再打印被删除的长章节。

## 9. 验收标准

改版完成必须证明：

1. HR 和法务的 24 个标题全部替换为本设计中的直白标题；
2. 展开任何场景只看到五项指定信息；
3. 每个可核验公司案例都能点击到支持该实践的来源；
4. 无可靠案例的场景明确显示“暂无公开可核验案例”；
5. 页面只保留首屏、矩阵、场景和三个优先启动项；
6. 筛选、矩阵定位、展开、返回入口和打印仍正常；
7. 390px 手机宽度无横向溢出，来源链接和场景按钮可用键盘操作；
8. 两个桌面交付页面与工作树版本一致。
