# 首页主导航与文章概要设计

## 目标

同时解决首页两个可读性问题：

1. 顶部“知识库 / AI机会雷达”主导航过小、不醒目。
2. 部分文章标题下方仍显示“位于本次更新窗口、主题为……”的系统占位说明，而不是文章概要。

## 已确认的视觉方案

采用方案 A“放大的主导航”。保持现有暖白、深绿和编辑型页面风格，不改变品牌区、首页正文、雷达页面或导航信息架构。

### 桌面端

- 主导航字号：16px。
- 单个导航项最小点击高度：48px。
- 左右内边距：18px。
- 当前栏目：深色文字、3px 下划线。
- 未选中栏目：使用比现状更清晰的中深灰绿；悬停和键盘聚焦时使用鼠尾草绿色强调。
- 保持足够的可见焦点样式，不以颜色作为唯一状态提示。

### 移动端

- 两个导航项继续等宽排列。
- 字号回落到 14–15px，最小点击高度 44px。
- 保留 3px 当前页指示线，避免因缩小字号而失去栏目识别。
- 不增加横向滚动。

## 文章概要方案

### 数据现状

浏览器索引共有 469 篇文章，其中 418 篇已有实际内容概要，51 篇的 `coreView.zh` / `summary` 是“该文位于本次……更新窗口，主题为……”格式的占位说明。受影响文章分布为：BCG 16、Anthropic 7、Bain 3、MIT 5、McKinsey 20。

### 内容规则

- 保留已有 418 篇真实概要，不进行无必要改写。
- 仅处理 51 篇占位概要。
- 每篇概要依据已归档中文全文提炼为 1–2 句中文，优先回答“文章讨论什么、给出什么主要判断或方法”。
- 概要不复述标题，不写更新时间窗，不添加原文未支持的数据、公司案例或因果结论。
- 如果中文全文不足以支持可靠概要，使用明确回退文案：“暂无可靠概要，点击查看归档全文。”，不得根据标题猜测。
- 概要写回规范数据源 `work/normalized/articles.json` 的 `coreView.zh`，再通过现有生成流程同步中文阅读页、知识库 corpus 与 `web/data/articles.js`，避免只修改生成产物造成下次重建回退。

### 页面呈现

- 文章列表继续在标题下显示 `article.summary`，无需增加新字段。
- 文章详情弹窗继续显示同一概要，保证列表与弹窗一致。
- 概要默认显示完整文本；现有列表布局可通过 CSS 控制行宽和间距，但不截断到只剩标题改写。

## 实现边界

- 修改 `web/styles.css` 的主导航样式。
- 更新 51 篇规范记录的 `coreView.zh`。
- 重新生成中文 HTML 阅读页、知识库 corpus 和浏览器文章索引。
- 同步受影响产物到桌面交付目录。
- 不修改文章标题、评分、主题分类、正文、来源链接或雷达数据。
- 不改问答 API 与模型配置。

## 验证

- 静态契约覆盖桌面与移动端导航字号、点击高度、当前页指示线和焦点状态。
- 数据测试确保 469 篇文章均有非空概要，并且不存在“该文位于本次……更新窗口，主题为……”占位模式。
- 对 51 篇更新记录检查概要与中文全文的来源一致性；至少抽查五个来源各一篇。
- 重新运行中文阅读页验证、corpus 验证和完整测试套件。
- 浏览器检查桌面与移动端导航、列表概要和详情弹窗。
- 确认桌面部署文件与工作版本一致，且本地知识库仍可通过 `http://127.0.0.1:4318/` 打开。
