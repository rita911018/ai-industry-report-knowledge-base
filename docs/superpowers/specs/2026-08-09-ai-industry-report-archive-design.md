# AI 行业报告归档、知识网页与 Insight Radar Skill 设计

## 1. 目标与已确认范围

在桌面创建 `AI行业报告`，将五份输入 HTML 按各自 `<title>` 建立一级文件夹，归档其中关联的 418 篇唯一文章，并为所有英文文章提供完整中文译文。

同时交付：

1. 一个统一知识网页，整合五份 HTML 的 418 条洞察记录；支持检索、筛选、提问、引用来源、查看本地原文和打开官方原文。
2. 一个可复用 Codex Skill，用于从指定官方来源发现 URL、提取正文、建立证据、生成多维标签并评分。

已确认的模型边界：

- 文章完整翻译由 Codex 完成，不安装本地模型。
- 网页问答使用用户后续提供的 DeepSeek API。
- 网页默认支持 `deepseek-v4-flash`，并可切换 `deepseek-v4-pro`。
- API Key 只由本地服务从环境变量读取，不写入 HTML、JavaScript、知识数据或日志。

```text
├── Bain Six-Month Insight Radar · 2026-08-02/
├── AI行业报告知识库/
└── 归档总清单.csv
```

每个 HTML 标题文件夹包含：

```text
<HTML 标题>/
├── 雷达原始页面.html
├── manifest.json
├── manifest.csv
├── failed.json
└── articles/
    └── <序号>-<稳定短名称>/
        ├── 原始网页.html
        ├── 英文原文.md
        ├── 中文全文.md
        └── metadata.json
```

`原始网页.html` 保存抓取快照；`英文原文.md` 只保留正文、标题、作者、日期、图表说明和正文链接，排除导航、Cookie、推荐阅读等页面噪声。`中文全文.md` 与英文正文按标题和段落顺序完整对应。

## 4. 归档流水线

### 4.1 HTML 解析

针对五种现有 DOM 结构建立适配器，统一输出 article record。先验证：

- HTML `<title>`；
- article 卡片数量；
- 官方来源 URL 数量；
- 记录 ID 和 canonical URL 唯一性；
- 原页面已有标题、摘要、证据、标签、评分和置信度。

解析后必须满足 `116 + 25 + 29 + 38 + 210 = 418`。

### 4.2 下载与正文提取

按来源限制并发，使用超时、退避重试和断点续传。每条 URL 进入且只进入以下状态之一：

- `downloaded`：快照和正文均成功；
- `thin`：页面成功，但公开正文仅有摘要、视频或播客说明；
- `blocked`：登录、反爬或地区限制；
- `failed`：网络或解析失败，保留原因和最后一次状态。

下载后保存最终 URL、HTTP 状态、抓取时间、内容类型、正文字符数和 SHA-256。不得用搜索摘要代替文章正文。PDF、视频或播客若只有 transcript 才作为全文；否则明确标记为薄内容。

### 4.3 Codex 全文翻译

仅翻译已抽取的正文，不翻译导航和广告。按语义段落分批，保留：

- 标题层级和段落顺序；
- 人名、组织名、产品名和链接；
- 数字、货币、日期、单位和公式；
- 否定、比较、条件、因果和不确定性；
- 图表标题、脚注与证据边界。

英文原文始终作为权威层，中文不得覆盖原文。每篇译文写入翻译状态、完成时间、段落数和质量检查结果。

### 4.4 完整性审计

归档完成条件：

- 418 条均出现在总清单；
- 每条都有来源 URL、雷达归属和最终状态；
- 成功项同时存在快照、英文正文、中文全文和 metadata；
- 英中标题层级与段落覆盖一致；
- 译文中的数字、日期、百分比和 URL 与原文一致；
- 失败项不能静默跳过，必须进入 `failed.json`。

## 5. 统一知识网页

### 5.1 页面能力

一个主页提供：

- 五个来源总览与 418 条覆盖统计；
- 按来源、日期、主题、优先级、置信度和分数过滤；
- 中英文关键词搜索；
- 文章详情与中英文切换；
- 本地原始快照、中文全文和官方原文入口；
- 对话式问题输入、历史问题和引用证据面板。

### 5.2 检索与问答

浏览器把问题发送给本地服务。本地服务先在文章标题、核心观点、关键证据、影响、业务含义和全文分块中检索，再只把 Top-K 证据块发送给 DeepSeek。

生成流程：

1. 双语查询归一化；
2. 来源/类别/日期过滤；
3. 关键词/BM25 初检；
4. 证据重排；
5. DeepSeek 生成结构化答案；
6. 服务端验证引用 ID 均存在；
7. 页面渲染结论、证据、边界和来源卡片。

每个事实性结论必须引用一个或多个 record/chunk ID。模型只能引用传入的证据；证据不足时明确回答“不足以判断”。分析推演必须标注为“分析判断”，不能伪装为来源事实。

### 5.3 DeepSeek 接口

- Base URL：`https://api.deepseek.com`
- 默认模型：`deepseek-v4-flash`
- 深度分析：`deepseek-v4-pro`
- 密钥：环境变量 `DEEPSEEK_API_KEY`
- 浏览器永远不接触密钥。

本地服务提供 `/api/health`、`/api/search`、`/api/ask`。未配置 Key 时，浏览与检索仍可用；问答区域显示明确的配置提示。

## 6. 反推的 Insight Radar Skill

Skill 名称为 `building-source-insight-radars`，放在 Codex 规范目录并同步到其他 Agent。

核心工作流：

1. 定义官方域名、发现入口、日期窗口、受众和覆盖边界；
2. 用 RSS、sitemap、索引和正文日期建立候选账本；
3. 规范化 URL、去重、抓取正文和保存快照；
4. 区分来源事实、分析归纳和业务推演；
5. 建立可定位证据和限制条件；
6. 生成主分类、辅助标签、地域、时间范围和业务适用域；
7. 使用评分 v1.0；
8. 输出优先级、独立置信度、管理摘要、逐项分析和来源索引；
9. 验证覆盖恒等式、评分求和、引用和可复跑性。

评分 v1.0：

| 维度 | 权重 |
|---|---:|
| 内容价值 | 35 |
| 影响广度 | 25 |
| 目标相关性 | 25 |
| 证据强度 | 15 |

总分是四项之和。便携默认优先级为：`90–100 Must Read`、`80–89 Track`、`0–79 Reference`；若语料采用不同覆盖策略，必须重新校准阈值并记录版本。

置信度独立于总分和优先级：High / Middle / Low 均须附理由。高相关性不得掩盖薄证据，厂商案例、自报调查、预测、相关性研究和跨行业迁移必须明确降权或限定边界。

## 7. 测试策略

### 7.1 归档测试

- 适配器分别通过五份 HTML 的黄金样本；
- URL、ID、文件夹名和 manifest 一一对应；
- 断点恢复不会重复下载或覆盖已完成译文；
- 快照与正文指纹稳定；
- 418 条覆盖审计通过。

### 7.2 翻译测试

- 数字、日期、单位、货币、百分比和 URL 自动比对；
- 标题及段落数量核对；
- Must Read 和每个来源的随机样本人工复核；
- 失败或不确定段落进入复核队列。

### 7.3 网页测试

- 桌面与移动端布局；
- 中文和英文搜索；
- 来源、分数、优先级过滤；
- 本地与官方链接；
- 无 API Key 时的降级体验；
- 有 Key 时的检索、逐句引用、矛盾处理和拒答；
- 引用 ID 不存在时服务端拒绝返回答案。

### 7.4 Skill 测试

采用 RED–GREEN–REFACTOR：先记录无 Skill 时对证据定位、覆盖声明、评分阈值和置信度处理的遗漏；再使用 Skill 处理不同来源的代表性 URL；最后验证结构、评分、引用和边界能跨来源复用。

## 8. 非目标与边界

- 不把咨询公司或厂商主张视为独立事实证明。
- 不声称覆盖来源机构整个网站，只声明对已配置发现路径的覆盖。
- 不绕过登录、付费墙、验证码或访问控制。
- 不把搜索摘要、导航文本或相关推荐当作正文。
- 不把中文翻译当作权威原文。
- 不在任何前端文件中保存 DeepSeek API Key。

## 9. 验收标准

任务完成必须同时满足：

1. 桌面存在 `AI行业报告`；
2. 五个一级文件夹名称与各 HTML `<title>` 一致；
3. 418 条均有可审计状态；
4. 所有可公开读取的英文正文均有完整中文译文；
5. 统一网页能浏览、搜索、过滤、引用和打开来源；
6. 提供 DeepSeek Key 后，网页能生成基于证据的带引用答案；
7. Skill 已验证并完成 Codex→其他 Agent 同步；
8. 自动检查、样本人工复核和最终清单均通过。
